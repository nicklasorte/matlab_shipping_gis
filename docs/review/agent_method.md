# Method review: paper versus code

Reviewer: method (AI agent). Scope: ship filter, route rules, charted lanes and racons, distance and zone method, land and coastline layers, and every parameter and count the paper states. Sources: `docs/review/paper_under_review.md`, the code at the repository root and in `python/`, the outputs in `outputs/2024_2025`, `outputs/2024`, and `outputs/2018_2019`, the cached inputs in `data/`, and public NOAA, Census, and eCFR pages.

## Summary

Most stated parameters match the code: the 0.01° grid, the 22–50° N and 66–130° W limits, the 104 Wednesdays, the ship types, the 100 m length test, the IMO rule, the 4-ship and 2-ship thresholds, the 50 km port radius, the 25 km tug-barge and shore-link distances, the 6,371 km sphere, the 0.005° simplification, and the band table. Tables 1, 2, 3, 5, 6 and the Hawaii, Alaska, and Puerto Rico counts match the run logs and CSV files. Four problems could change routes or zones. First, the zone and band files count Canadian, Mexican, Cuban, and Bahamian land as "ship water," because the land mask holds only U.S. states. Second, the cached NOAA fairway file used for the lower-48 run holds only 28 mid-Atlantic features. The live layer holds 291 features in the grid, including the Gulf safety fairways and the Pacific traffic separation schemes. Third, a theme-name mismatch drops every "Traffic Separation Schemes" polygon. Fourth, the route above Baton Rouge rests on 2 river vessels that the 2-ship port-approach rule lets in. Those vessels also sail the upper Mississippi to Winona, Minnesota. Many smaller findings are number mismatches between sections. These come from the appendix and stability scripts, which use different route sets than Section 1: Python AIS-only cells, and a 105-day base. Others are wording that describes the method more tightly than the code runs it.
